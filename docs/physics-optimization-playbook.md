# 物理模拟性能优化：Agent 决策手册

本文是跨角色的实验方法，不提供任何角色专属参数。源 PMX、实际骨架、各分区刚体/关节和目标动作决定候选；不得复制其它角色的数值或把降低精度称为无损优化。通用测量要求与状态定义见 [Agent 物理工作流](agent-physics-workflow.md)。

## 先确定瓶颈，再建立候选

1. 锁定目标工程、mesh、骨架、动画、分区 PA、最终 ABP、源数据及指纹；保留已认可版本，所有候选使用独立路径。确认场景实际运行的是最终 ABP，而不是生成中间资产，也没有绕过物理节点。
2. 在同一地图、视口、画质和动作下，采集无物理、同步物理基线、当前候选。先核对实际运行帧数、游戏时间步、预热、进程退出和帧率上限回读。数据无效时修采集，不调求解器。
3. 比较平均与尾部帧耗时，同时看 Game/Draw/GPU 及物理相关线程或 trace。无物理对照也慢时，先排除共同的渲染、动画、材质、线程调度或环境负载；不能把总帧率差直接当作物理线程耗时。同步、延迟候选的差异也要区分调度收益与真正减少计算量。
4. 记录每个分区的动态骨/刚体数、关节数、shape 数、碰撞过滤和求解设置，找到成本与可见问题集中的分区。不要仅凭骨名或“无顶点权重”删除骨、关节或碰撞体；源 PMX 约束、锚点和蒙皮依赖必须先审计。

## 候选顺序：一次只变一个因素

| 候选 | 适用判断 | 必须核对的代价 |
|---|---|---|
| 分区调整 position iterations | 高成本分区有收敛余量；逐个分区、逐档实验，先保持其它分区不变 | 接触穿插、抖动、拉伸、急停和低帧率稳定性；不能整角色统一降到某值 |
| 调整 fixed time step / 子步预算 | 确认成本主要来自物理更新频率，且实际动作可接受较低频率 | 快速动作、碰撞漏检、关节收敛和帧间抖动；不要与迭代数同时改 |
| 同步与 Deferred 对照 | 求解/等待阻塞主线程，且动画容忍上一帧结果 | 明确接受一帧延迟；比较移动、转向、卡顿和相机跟随，不把调度收益说成计算量消失 |
| 运动空间与输入约束 | 动画骨在组件内部持续位移，或循环回跳使模拟体追赶目标 | 选存在且非模拟的稳定 base bone；分别审查局部/世界阻尼与速度、加速度输入上限，不能靠周期重置掩盖问题 |
| 个别分区改为跟随动画 | 该部位的独立动态效果并非交付目标，且已获得明确视觉认可 | 这是效果/功能降级，不是原物理效果的无损优化；记录取消了哪些独立运动，并单独对照画面 |
| 精简物理表示 | PMX 语义、权重、约束、碰撞 mask 和接触审计证明某体/关节确实冗余 | 保留源分组的双向 per-shape 过滤；不得凭性能诉求添加衣裙代理、放宽 mask 或删除必要锚点 |

改变一个候选后，先重新生成数值/碰撞证据，再看连续 GameViewport 画面和性能。若求解预算变小但衣物出现穿插、飞离、明显相位延迟或对低帧率更敏感，撤回该候选；不能以平均 FPS 改善单独宣布成功。尤其不要通过锁住骨盆、每圈强制复位、降低渲染质量或关闭其它视觉效果来冒充物理优化。

## 静态、动态与游戏范围分开验收

- 无目标骨架动画时仍要做静态数值与真实 PIE 静态跑分，比较无物理、同步、候选；结果仅说明静止求解负载。不能标记走跑、根运动或游戏可用。
- 有动画后另建动态版本，重测动画内部位移/循环、组件连续移动转向、低频更新和卡顿，再做相同条件的真实渲染性能对照。合成时间步稳定性不等于真实帧率。
- 性能必须按目标硬件、视口和画质预算判断；每个 case 多轮交替，保存原始报告、输入指纹与退出码。候选超预算、控制也超预算、测量无效、画面不合格应分开记录，不允许合并成“通过”。
- PIE 单角色通过只是当前测量范围内通过。打包游戏、长时间运行、多角色、LOD、CharacterMovement/根运动集成与用户认可另列状态；没有证据就保持 pending。

## 每个候选的最小记录

记录：假设与可证伪观察、唯一改动、分区和参数前后值、目标/控制资产路径及哈希、静态或动态 scope、数值/碰撞/视觉/性能报告、实际视口和画质、平均与尾部帧耗时、进程退出码、效果损失、结论和下一步。保留失败数据；不可用失败实验的偶发高 FPS 选择胜者。最终只把同时满足效果和预算的候选推荐进入下一阶段。
