# Agent 材质闭环：证据、隔离对照、截图、验收

本流程不要求动画。没有源动画会阻止动态重定向、移动物理、动态 SDF 验收，不会阻止材质的静态视觉工作。脚本负责重复操作和证据完整性，agent 必须实际打开图片判断效果。

多材质族任务按 [协作规程](agent-collaboration.md) 将必要的 SDF、眼睛、头发、袜类专项分配给独立执行者，统一 mesh/槽/UV 输入；共享父图和映射由一个写入者维护，构建/采图排队。最终可由具备图像工具的另一智能体直接审阅原图与目标需求，不能仅复述实现者总结；小改动只审其影响范围。

进入构建前先按 [材质族设计](material-families.md) 完成 `material-design.md`：区分不同表面的计算与渲染层，建立目标效果和实际工具能力的对应关系。本文负责预览和验收闭环，不能代替眼睛/头发/丝袜等专用实现。最终不要把一个通用 Master 的基础贴色当作角色级材质完成。

执行顺序及新增工具见 [材质迭代与交付](material-iteration-and-delivery.md)：先取得最小基线画面，再做局部效果；新环境先小探测，纯材质迭代复用网格，实际输入和降级项进入交接检查。不要把第一轮截图推迟到所有角色系统完成之后。

## 1. 从源资料建立可追溯关系

先按 [目标图建档与检索](target-image-lookdev.md) 从 PMX 素材目录发现候选、看图分区；将已采用的丝袜/布料/脸部/全局等条目写入 catalog。每轮设计和渲染审核前按任务标签查询原图与区域，不要求用户逐张给图，也不把目录中所有图片自动当美术目标。无适用图照常继续。

读取 source audit、Blender manifest、PMX 材质参数和实际贴图。逐项建立：纹理文件 → 引用材质槽 → UV/遮罩通道 → 材质用途 → 采用/不用的理由。不能让 `Socks.png` 之类未分类贴图没有结论地流入最终交付；名字只提供候选，需检查像素、alpha、UV 覆盖及对应身体区域。

为本角色复制 `templates/material-review.md`。明确区分用户要求、源材质已有特征、agent 提议的可选风格。用户已要求的丝袜厚度/高光、描边或边缘光，不能再以“按需功能”为理由跳过；应创建隔离变体或明确缺少的能力/证据。反之，没有依据时不自动加黑丝、额外描边或全场景后处理。

白丝“厚度”可能是边缘色/高光造成的观感，也可能涉及覆盖、透射或几何轮廓；不能直接互相等同。按材质族文档的资产优先检查核实实际表面层、袜下皮肤及 UV/Alpha，再选择候选算法。保留原网格/权重，不把加厚几何或改透明模式当默认修复；每次仅对一个效果做对照。

## 2. 构建和 API 故障定位

执行 `material-check → ue-build → ue-validate → material-compile`。图连通、shader 编译和视觉表现分别记录。

- 连接失败应记录目标节点类、请求输入名、实际输入名和引擎版本。`ue_context.connect` 现在提供这些诊断。不要假定每个单输入节点都叫 `Input`；以安装版本源码/API 为准。
- 需要替换为等价节点时，记录表达式及其定义域，例如平方根换幂运算还须保留输入的非负约束。不要为消除错误改变计算语义。
- 可选 TextureSampleParameter2D 分支也必须有实际默认纹理。构建器现在拒绝空纹理或关键属性写入失败；占位纹理应按 Color/Normal/Masks 的采样类型选取，再通过实际 shader 编译确认，不能只“塞一张白图”。
- 当前通用主材质构建脚本没有创建 SquareRoot 节点。其它工程的这个节点修复不能因此被宣称已合入或普遍适用。

## 3. 独立预览，不操作用户当前关卡

黑图、曝光和基线审核按 [日光预览排错](daylight-preview-troubleshooting.md)。单 case 和多 case A/B 均默认使用场景/工程的默认曝光，不要求独立校准。固定 EV100 与 `environment_review` 都是可选项，不得为了开始材质对照而反复调曝光。

**默认直接使用 UE 安装目录的 Open World 日光场景作为材质测试基线。** 自有新编辑器进程加载 `/Engine/Maps/Templates/OpenWorld`，在内存中放置角色和相机，不创建自定义预览地图，也不保存引擎模板或用户关卡。保留天空、大气、天空光、太阳、地面及默认环境；不另建工程。不要用空黑背景加单灯作为唯一验收环境。暗室、夜景、特殊灯光是后续补充，不替代日光基线；用户指定其它环境时按实际要求适配并说明。

先看未改模板太阳的 Lit 图，**仅核对环境与取景**：天空和地面是否正常、人物是否在地面上、天空光/反射是否生效。随后用当前角色正面斜侧的主光做第一轮材质判断：脸部与暗部织物是否可辨、高光是否过曝、阴影与光照是否合理。斜侧主光下仍异常时先排查材质或环境，不能靠换方向挑选一张好看的图通过。整体过暗时先检查环境加载、相机曝光及灯光；不能用整体 Emissive、调亮贴图或关闭阴影掩盖预览环境问题。Unlit/WorldNormal 是诊断图，不代替正常光照验收。

复制 `templates/material_preview.example.json` 到角色配置目录，agent 根据模型调整：

- `mesh` 为已保存的本次角色网格；v3 不填写 `level`，防止误建/误用自定义地图。
- `environment.template` 固定为真实 Open World 日光场景，`model_location` 是审核后的角色根位置（厘米）。`[0,0,0]` 只是起点，检查脚底、地形高度和遮挡；不保证每个模型原点都在脚底。World Partition 地形/天空未加载时先显式加载预览区域，必要时适配工具；脚本会报错，不静默退回空关卡。引擎地图文件前后哈希必须一致。
- v3 的 `capture.mode` 使用可见编辑器视口 backbuffer；不要再填写旧 `width`/`height` 或 `minimum_width`/`minimum_height`。记录实际尺寸，但**没有最小尺寸通过门槛**，也不用 `-RenderOffscreen`、`HighResShot` 放大或离线输出分辨率冒充画质。只有无可绘制像素时才是技术性失败。旧 v1/v2 配置可复现，但不作为新的材质视觉验收依据。
- 相机必须声明观察目的，按 [主体取景契约](preview-framing.md) 填写 `azimuth/elevation/fov/framing`。全身按实际包围盒和视口比例自动留边，近景必须指定实际骨骼或包围盒相对位置及观察范围；不再用旧 distance/height 假装对准脸部。模板 front/side 方位只是候选，不保证是模型正面。模板先拍全身，agent 再根据实际模型添加脸部、丝袜等所需近景。
- 第一盏始终是 `DefaultDaylight`，仅写 `name`，保留模板太阳作为**环境核对锚点**，不保证它照亮角色正面。单光基线模板只用于查天空/地面/曝光；复制 `templates/material_light_sweep.example.json` 后，所有角色的首轮材质观察光一律从**角色自身正面偏左 45°**射来，不能仅把太阳当前 yaw 加 45°。模板的 `yaw_offset` 是非数字占位值，必须按当前 mesh 的真实正面和场景中的角色旋转填写；必要时调整太阳高度 `pitch`。背后来的光不能作主验收图。每张图记录实际太阳参数，保留模板天空光，不叠加第二盏主太阳；旧 `6` 强度不能照搬到日光基线。
- 方向换算：设角色**当前世界正面**的水平 yaw 为 `F`，Open World 模板太阳的初始 actor yaw 为 `S`。UE 的 +X 是前、+Y 是右；站在角色正面左侧 45° 的**光源位置方向**为 `F−45°`，而 Directional Light 的箭头/光线指向角色，因此所需太阳 actor yaw 是 `F+135°`。当前预览器实际设置 `S + yaw_offset`，故填写 `yaw_offset = wrap(F+135°−S)`。例如角色真正面沿世界 +X（`F=0°`），应使太阳 actor yaw 为 `135°`，**不是 45°**。先确认模型本身的正面、场景旋转以及 `initial_sun.yaw`；不要把相机 yaw、模型局部 yaw 或绝对 actor yaw 直接填进 `yaw_offset`。这只是方向填写规则，不添加额外自动校验；看图仍是外观判断依据。
- v3 的首轮材质 profile 设置 `primary_light` 为经模型校准的斜侧光；采集器**先拍主观察光**，再补拍 `DefaultDaylight` 环境锚点。配置列表首项仍须是未改模板太阳，实际太阳回读照常记录。该字段只调采集顺序，不修改或保存 Open World 模板光源。Agent 必须先打开斜侧主光原图，记录各材质族是否正常及具体缺陷；有缺陷就先在此光下修正/重拍，不能直接靠换光向放行。若主光仍正面背光，先修正本角色 profile 的 yaw/pitch，而非改材质发光。
- `exposure_ev100: null` 在 Baseline 和多 case A/B 中均保留模板/工程曝光，不创建固定曝光覆盖。默认不调曝光、天空光或全局后处理。只有实际环境异常或明确需要受控亮度对照时才选固定 EV100；固定曝光要求扩展亮度范围，不支持时报告限制，不擅自修改项目设置。`environment_review` 可省略；主动填写时仍校验原图、报告和条件，不能伪造已看图。
- 日光下至少选择有辨识力的两个观察角度，不意味着必须改变灯光；匹配视角的 A/B 使用相同曝光策略和光照。自动曝光可能随画面适应，同策略不保证实际曝光完全相同，不能仅凭亮度改变断言材质改善。固定预热时间不能证明贴图加载；每张截图前核对角色材质实际引用的 /Game Texture2D 驻留 mip，未完整加载就继续等待并请求加载，超时记录贴图及 mip，不接受模糊图。天空捕获还未稳定时另行增加预热。
- **斜侧主光下外观确认正常之后**，才复制 profile 到新运行，保留该主光和默认太阳，按当前角色和待测材质效果增加第二观察方向；不要在首轮就填一组未校准的光向。新的材质交付至少选一个对光向敏感的已审阅效果，在**同一报告、同一 case、同一机位**下拍默认太阳与实际方向相差至少 20° 的 Lit 图；agent 打开主光和新方向原图，记录阴影过渡、高光如何移动、失败或局限。优先仅为该局部效果创建独立的近景转光 profile，避免把七角度脸部扫描扩展成所有材质×所有机位的大矩阵；保留同一材质版本和默认曝光策略。`material_review_contract=2` 会核对逐图实际太阳回读，光源名称不同但方向没变不能过关；另需在材质审阅记录中引用**先于新方向运行**的主光初评图与结论。角度门槛不保证效果好；朝向选择、是否补仰角/逆光及审美结论仍由 agent 基于画面判断。
- 默认 `modes: ["Lit"]`（省略 modes 也按 Lit），只有实际外观图进入相机×光照×案例矩阵。Unlit、WorldNormal 非必要不采集；贴色或法线出现疑点时，用 `diagnostic_captures` 指定某一个案例、机位和光照，只补一张对应诊断图。不要随全部转光角度和材质候选重复拍诊断图。旧配置显式填写多 modes 仍可复现，但新任务优先采用精简策略。
- 第一个 case 严格为 `{"name":"Baseline","slots":[]}`。其它 case 可以用组件级材质替换或临时标量参数。未知参数报错，不能静默忽略。

按需单张诊断示例（与 cases、cameras、lights 中的名称精确匹配；不需要时省略或留空）：

```json
"diagnostic_captures": [
  {"case":"Baseline", "camera":"Front", "light":"DefaultDaylight",
   "mode":"WorldNormal", "reason":"检查肩部出现的法线接缝"}
]
```

需要检查底色时改为 `mode: "Unlit"`。确实同时有两种问题时可以分别加一条；每条必须写明诊断目的，不自动补齐三种模式。诊断图不替代 Lit 外观 A/B。

单槽材质候选（将索引、路径、参数替换为实际已审核值）：

```json
{
  "name": "StockingHighlight",
  "slots": [{"index": 3, "material": "/Game/PMX4UE/Character/v1/Materials/MI_Stocking_Test", "scalars": {"Roughness": 0.6}}]
}
```

实验材质先在独立路径构建/保存。不能修改共用父材质然后将 Baseline 当作“修改前”。若比较高光和厚度，两者拆成两个 case；是否组合由单项结论决定。

描边 case 可加 `"outline":"/Game/.../M_Outline_Test"`，表示全槽通用候选；对象形式可指定脸/发专用材质和排除槽，见 [面部 Overlay](face-outline-overlay.md)。嘴角黑点须先做无描边对照，再按实际 UV 校准局部抑制，不照搬旧椭圆。边缘光 case 可加 `"depth_rim":"/Game/.../M_DepthRim_Test"`；工具仅在自有预览进程临时启用 `r.CustomDepth 3` 并回读，不写项目配置。两项都只影响预览实例，不保存引擎日光地图。构建候选用 `scene-effects-build`，逐项选择和交付要求见 [场景效果闭环](scene-effects-workflow.md)。现有算法是可适配的起点，不自动适合任意角色。

所有 `unreal.Rotator` 使用命名参数 `pitch=..., yaw=..., roll=...`。不要依赖位置参数顺序：它曾把模板太阳的 pitch/yaw 填入错误轴，导致黑天空。预览逐图回读三个轴，与请求方向比较；配置列表首项保留模板太阳，设置 `primary_light` 后采集首图为斜侧主光。仍需实际看天空、地面和脸部，参数正确不自动代表曝光或画面正确。

审核后设 `reviewed=true`，工作单增加/更新：

```json
{
  "material_preview_profile": "<角色配置目录的绝对路径>/material_preview.json",
  "material_preview_run": "v1"
}
```

这些字段放在工作单的 `pmx4ue` 对象内。运行：

```powershell
python pmx4ue.py run --config "<工作单路径>" --stage material-preview
python pmx4ue.py run --config "<工作单路径>" --stage material-preview --execute
```

脚本启动自己持有的新完整编辑器进程，不连接用户当前编辑器；启动标记、目标工程及初始地图三重检查后直接加载 Open World。v3 不创建/保存任何地图，不调用旧的按类型清理角色/灯光或 SaveDirtyPackages，也不保存原网格/材质。A/B 覆盖仅存在于该进程内。

旧 v1/v2 结构仍可读取，但现行截图执行器要求迁移到 v3，不再执行旧单灯/复制地图路径。旧 v3 也须补主体取景配置并重新采图，旧报告没有 framing 回执不能通过新验收。迁移时从示例新建 profile 和运行名，移除旧 level、distance、height，重审目标部位、位置和曝光；不要只改 schema 或伪造回执。模板不可用或当前引擎路径变化时核对实际安装内容/API 后显式适配。

材质变体、头发描边分槽、动态 SDF 等特殊需求由 agent 根据源码定向扩展；不要因工具只覆盖默认效果就把需求默默删掉。

## 4. 截图落盘，而不止“已发出命令”

`ue_material_preview.py` 直接调用插件公开的 UE Python 方法，不依赖聊天会话有没有同名 MCP 截图工具。旧 `ue_build_character.py --mode preview/full` 已禁用，先 build 再用新阶段；旧 `_destroy_previous` 也不再删除当前地图对象。

采集会重新检查基线和变体的材质父链编译，并等待实际贴图 mip 驻留；若 60 秒仍未完成则失败并保留逐贴图证据。捕获时重新验证角色可见性与全身/部位投影范围，拒绝隐藏、裁切和过小主体，逐图保留 framing 回执。v3 原生接口读取同一可见视口当前 RGB、将普通场景截图 Alpha 固定为255并保存 PNG；脚本检查完整性、CRC、实测尺寸并解码像素，透明通道异常立即拒绝。RGB 近黑/过曝/恒定只给出人工排查警告，不自动判断材质。原生截图复制到本次产物目录、验证字节一致并保存报告后，删除本轮原生临时重复副本，保留产物原图及哈希；清理失败留副本并记录。文件名包含唯一运行标记，避免读到旧图。详见 [截图分阶段保留](capture-retention.md)。原生修复需编译和新进程重新采图，不把旧图修补副本当作新截图。

产物位于 `<artifact_dir>/material_previews/<material_preview_run>/`：

- `material_preview.json`：完整配置、引擎/provider、直接加载的日光地图及源哈希、已加载环境 Actor、天空光强度、曝光策略、逐图实际太阳参数、相机、视图模式、逐图贴图驻留 mip、图片路径/哈希、实测视口尺寸、截图来源、`r.ScreenPercentage` 设置值、编译结果。该设置值不证明内部实际着色分辨率。
- `captures_<运行标记>/`：可供 agent 打开的实际图片。
- v3 不生成基线地图；复查时用报告配置在日光场景重新启动自有预览进程。不要保存被临时角色/灯光覆盖的 Engine 地图。

运行器检查图片完整性、矩阵覆盖、图片及项目资产哈希。v3 还拒绝离屏来源、尺寸不符、未驻留的贴图 mip 或日光地图文件变化；**不以像素尺寸判定清晰度**。状态查询也追踪这些指纹。引擎/插件外部依赖只列路径，不声称完整二进制指纹覆盖，交接需保留版本。截图分辨率不是性能测试 viewport 分辨率。

**`captured_visual_pending` 仍不代表画面正确**：有效 PNG 也可能黑屏、取景错误、角色太小，甚至虽已驻留的贴图也可能因过滤、LOD 或时域处理显得模糊。agent 必须打开原尺寸图片（不要用聊天缩略图代替）检查头发丝、衣服纹理、袜边和高光边界；若局部细节模糊，对照 Unlit、Lit 及原贴图排查贴图 mip/LOD、过滤、TAA/TSR、景深和运动模糊，先定位成因，不直接提高锐化或重做材质。需记录至少一张局部近景和一张全身图；近景仍糊则不得签收材质。必要时增加预热、纠正相机或补近景，并使用新运行名重跑，不覆盖失败证据；v3 不生成新地图路径。图片产物不全、接口缺失或截图失败时记 `capture_failed/blocked`，不能退回“编译通过所以完成”。无需启动另一个空白项目。

## 5. 实际看图和交付

填写 material-review，每个效果至少引用基线与变体的相同视角/光照截图，记录观察、选择、缺陷和下一步。若提供了目标图，按 [目标图驱动的材质迭代](target-image-lookdev.md) 逐区域对照：每轮材质调整后重拍可比的全身/近景，写明尚存差距和保留/再改的理由，不以“色彩接近”代替材质计算验收；无图则照常按模型和文字要求审核。需看正面/侧面/局部和改变光照后的稳定性，不只挑一张好看的图。无法读取图像的 agent 将视觉审核交接给有图像能力的 agent/用户，保留 pending，不自动签字。

从截图得到的仅是当前模型的静态外观结论；动态头骨 SDF、透明排序随动作变化、物理碰撞及游戏性能仍分别走各自验收流程。材质变更后旧截图立即过期，需重新采集。

每轮看图并采用/退回候选后，按 [截图分阶段保留](capture-retention.md) 更新基线、当前候选与故障 pin，明确退役无独立价值的旧预览，生成引用保护的只读清理计划。获覆盖该范围的用户授权后才执行；不必等待最终角色交付，但不得删除仍被审阅/交付或子任务使用的截图。
