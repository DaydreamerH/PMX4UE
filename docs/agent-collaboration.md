# 多智能体协作与能力选择

主智能体负责模型整体方案、依赖顺序、UE 执行调度与最终资产组合；对子任务的结果仍须整合判断。本文是可迁移的委派规程，不要求某个平台或固定模型。`pmx4ue.py` 记录阶段并持有工程锁，但不负责启动智能体、选择模型或计费；这些由宿主实际提供的委派工具完成。

## 何时分工

有可用子智能体工具时，优先委派下面独立且有明确产物的工作。简单、关键路径上的一步操作由主智能体直接完成；任务太短、输入未稳定或协调成本超过收益时，记录简短理由即可。默认同时运行最多两个工作智能体，主智能体继续处理不依赖其结果的任务；只有存在更多独立工作且预算允许时才扩展。子智能体默认不继续嵌套委派。

| 阶段 | 可委派任务 | 必须保留的依赖 |
|---|---|---|
| 初始盘点 | 已生成报告的槽/纹理整理、PMX 刚体分组分析、骨架语义初审 | 主智能体汇总单位、真实模型身份及一致的语义映射 |
| 骨架优化 | 实际导出/UE 层级、主链和变形证据的独立审阅 | 优化产物与导入验收确定后，才向 IK/物理交付选定 mesh |
| 材质基线之后 | 脸部 SDF、眼睛、头发或袜类的独立方案、局部实现脚本 | 必须共享同版 mesh/槽/UV；共享 Master、映射表和构建入口由一个写入者维护 |
| 材质视觉验收 | 打开原尺寸截图与可选目标图，检查计算和可见效果 | 主智能体统一采图；没有实际图像能力的智能体只做数据/图连接审阅 |
| 物理 | 源 PMX 双向 mask/关节分析，或已有性能报告的瓶颈分析 | 分区规划可先分析；实际构建需已验收骨架，动态测试需已验证动画 |
| 工具适配 | 单一 API、坐标转换或独立文件的修复 | 每个文件只有一个写入者，统一整合后执行相应验证 |

骨架发生层级/绑定变化、材质采用新光照算法或进入最终视觉交付、物理准备宣称达到性能预算时，安排一次独立审阅最有价值。宿主支持且工作可分离时委派；缺少委派能力则由主智能体依据同样的原始证据完成专项复核，并标明是同一智能体，不能虚构独立审核。小参数调整可沿用同版的已审阅前提，仅复核实际变化。

## 按能力和成本选执行者

派发前读取宿主实际暴露的可选执行者、推理档位、工具/图像能力及价格信息。以下是任务需求标签，不是固定模型别名，也不写入全局模型设置：

| 能力档 | 适合的任务 | 不宜独立决定 |
|---|---|---|
| `basic` 基础 | 按已定义规则整理清单、核对路径/哈希、格式转换、单文件机械修改、汇总测试结果 | 删骨、猜 UV/通道语义、选阴影算法、签收视觉或物理效果 |
| `specialist` 专项 | 边界明确的骨链/碰撞分析、单材质族实现、API 适配、具备图像能力的局部看图 | 缺上下文的跨系统架构变更与最终兼容性取舍 |
| `advanced` 复杂 | 未知模型语义、蒙皮/约束重构、SDF 光照与编码诊断、模拟空间/低帧率问题、跨系统集成 | 仍需实际证据；能力档不替代 UE 验证和用户认可 |

先用现成脚本完成确定性操作，只在需要解释或修改时安排智能体。满足必要能力、工具和上下文的执行者中，优先选择预期总成本较低者；同时考虑重试和主智能体整合成本，不能只看单次价格。廉价候选缺少图像工具时，换合适的执行者或由主智能体看图，不能让它仅凭报告判断外观。

任务复杂度与模型价格不是同一件事。只有宿主提供可靠价格时才作价格比较；否则记录 `price_unknown`，按已公开能力选择，不猜金额或声称某个选项最便宜。宿主不允许覆盖模型、没有合适低成本选项或用户限定执行者时，遵守实际限制并沿用可用设置。能单独调推理预算时，确定性任务用较小预算，诊断任务增加预算；不靠降低预算掩盖未知。

基础任务出现语义歧义、专项任务需要改共享算法或约束、一次有依据的尝试仍无法验证时，返回证据并升级给主智能体或更高能力档。主智能体先区分任务不清、输入不足、工具失败和能力不足；补证据/修工具不等于必须升级模型。不得让多个执行者重复同一失败尝试。任务预算用宿主支持的成本、token、时间或尝试次数填写，无法技术限制时明确为计划预算。

## 派发、执行与整合

用 `templates/agent-coordination.md` 保存本轮分工；具体任务用 `templates/agent-task.md`。放在当前角色版本的产物目录中即可，不创建新的 UE 工程。小任务可使用模板中的核心字段，不要求每次建立完整团队。

1. **锁定输入。** 主智能体给出目标、必要参考、真实输入路径与版本/指纹、选定 mesh/skeleton、当前阶段及已知限制。材质任务按 `docs/target-image-lookdev.md` 查询目录档案，只传相关 image/region ID、原图位置/指纹和观察；审阅者仍须看原图。对子任务只传相关上下文；独立审阅先提供要求与原始数据/画面，避免只传实现者的结论引导其签收。
2. **确定所有权。** 列出可以写的具体文件、产物目录、候选资产命名空间和 UE 执行权限；未列出的内容默认只读。子智能体可以在独立脚本/候选文件中实现，共享工作单、材质映射、语义角色映射和最终交付由主智能体整合。只读审核产物写在自己的报告目录。
3. **统一执行。** 工程导入、插件构建/安装、UE 资产写入、预览截图和性能测试统一排队，一次一个工程执行者；可由主智能体执行或明确委派给唯一持有者。保留现有工程锁，不绕锁并发运行。当前运行器连离线阶段也持锁，离线分析可读取完成的报告或调用允许的只读工具，不为并行移除锁。性能计时期间暂停团队自身的构建、烘焙和其它重负载预览；不终止用户程序。
4. **取回实物。** 子智能体返回实际改动文件、候选配置、原始证据和未解决项；主智能体检查差异、输入版本和依赖，确认工具真正消费这些字段。没有产物或实际看图，状态保持 pending/failed，不能依据一段“已完成”消息推进。
5. **按变化重验。** 骨架/mesh 变化通知依赖任务，旧结果保持历史记录，新输入需要对应复核。单材质族实验不要触发无关骨骼重导出。主智能体统一采用或退回候选，并更新准确资产组合；不同智能体的多数意见不替代原始证据。

源动画缺失只影响对应的动作、移动物理或动态 SDF 验收，材质、骨架静态/采样检查和静止物理性能继续。无子智能体工具时以单智能体完成同样阶段，记录 `single_agent`，不为启动协作另建用户任务或要求用户安装服务。

派发被拒绝、额度不足或执行者中途失败时，保存失败状态与已有产物，释放它占有的任务/执行权；主智能体接手未完成内容或选择实际可用的执行者。不重复启动相同受限任务，不把失败审阅写成通过，也不因委派失败停下仍可完成的工作。

## 审阅和收尾

骨架审阅查实际主链、权重、旁支和导入来源；材质审阅查真实输入、图连接及已打开的全身/局部 Lit 图，不能只核对 Master 个数或截图文件存在；物理审阅查源 mask/关节、运动证据、原始控制/候选数据、测试条件、均值/P99 和退出码。结论可为通过当前范围、具体缺陷或缺证据，不以智能体评分自动批准。

`implemented`、`measured`、`agent_reviewed`、`user_approved` 分开记录；任务状态和角色交付状态也分开。子智能体通过只代表其任务范围，不能替主智能体宣称整角色完成。工作结束收回工程执行权并关闭不再需要的子智能体；任务书、结果及采用理由进入 handoff。资产清理仍遵循已有最终交接规则。

## 版本组合与局部实验复核

按 `docs/reference-implementation-transfer.md` 的实际协作经验，审阅对象是**准确资产组合**，不是“最高/最新版本”。记录候选 mesh、专项父图/实例、纹理、Overlay/额外 Pass、驱动及 AnimClass 的实际版本/指纹；允许复用多个已认可版本，不为目录统一重造资产。主智能体保存后重载核对正式入口，再交付审阅。

视觉子任务返回实际打开的原图清单、观察与缺陷；主智能体事后补齐图哈希时，分别记录看图者和元数据编写者，不把补录当独立看图。先看基线/候选与相关目标局部，具体问题才扩大，不照搬历史大矩阵。参考成功只证明其声明范围，不作为当前角色证据。

缺陷按“观察→证据→最小改动→对照→采用/退回”闭环，避免多方同时改 UV、深度、强度和槽位。最终组合的物理视觉失败及未测性能原样保留，专项通过不能覆盖整组合缺口。没有动态输入继续静态工作，但动态、表情和额外 Pass 游戏成本保持 pending。能力与价位规则不变。
