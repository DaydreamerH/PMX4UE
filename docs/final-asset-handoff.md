# 最终资产确认与旧版本清理

这是整个角色流程的**最后阶段**，不随构建、`delivery-check` 或 agent 自评自动触发。交付报告的 `evidence_complete_needs_human_judgment` 只说明证据一致，不是用户认可，更不是删除授权。旧试验、成功版本、源 PMX/贴图、原 mesh/骨架/场景在确认前全部保留。

上述保护针对 UE 资产及源输入；工具生成的重复临时截图和已明确退役、无在用引用的中间图可按 [截图分阶段保留](capture-retention.md) 提前管理。原生重复副本只在产物原图验证后清除；旧图须独立的引用保护计划与覆盖该范围的用户授权。不能用截图政策绕过本页的 UE 资产删除条件。

## 1. 确认最终组合

向用户展示 `delivery.json` 中逐项明确的 mesh、skeleton、材质及覆盖、IK、动画、物理资产、场景接入，附静态画面、转光、动作/物理、性能的已验证范围和未完成项。**用户确认这个具体组合后**才冻结清单和文件哈希；只认可某张截图、某项效果或“看起来不错”不等于认可全部版本或允许删除旧版本。若用户仅确认局部，保留其它方案。

## 2. 只读列清候选，不自动发现即删除

复制 `templates/retirement-candidates.example.json`，将 `candidate_namespace` 限定到本角色一个旧版本；每个候选逐一填写**精确 `/Game` 包路径**和替代理由。不得使用 `old*`、整个角色目录、Content 根、日期/版本名推测或文件系统批量删除。把复用 mesh、材质父图、纹理、物理资产、动画、关卡及用户指定保留项放入 `protected_assets`；最终 `delivery.assets` 自动受保护。

可用只读工具生成候选报告：

```powershell
python tools/asset_retirement_plan.py --delivery "<已确认的 delivery.json>" --candidates "<逐项候选.json>"
```

工具只读文件并输出候选路径、当前 SHA256 和交付文件 SHA256；**不会删除或判断 UE 引用安全性**。保存报告供审核。候选集有多个版本时分别列计划，不能用宽泛 namespace 合并。

## 3. 引用审计、单独批准、可恢复执行

在目标 UE 工程中，针对每个候选查硬引用、软引用、管理引用、Redirector、关卡/蓝图/材质父子链、选定资产的传递依赖和运行时动态加载路径。存在选定版本或非候选资产引用时先修复并重新验证，不能靠强制删除。UE 内置引用查询有盲区；动态路径、外部数据表和未加载内容要结合项目检查。无法证明安全的项从候选清单移出。

向用户提交**准确候选列表、哈希、引用审计、删除后保留清单及可恢复方案**，单独请求“批准删除这些资产”。用户未批准、项目/候选哈希变化或有未解除引用时停止。批准后保留 Git/工程备份或 UE 可恢复快照，仅通过 UE 资产系统按准确包路径删除，不使用 shell 删除 `.uasset`/整个目录；不要顺手清理工作流源码、Saved 报告或源 PMX。

删除后在 UE 重新打开最终角色、检查引用/材质/IK/物理/动画，复跑受影响验证和关键截图；重新生成最终交付指纹与 handoff。失败时按备份恢复并报告，不把“清理完成”写进旧证据。旧证据和可追溯记录保留；只清理由用户明确批准且无依赖的旧资产。
