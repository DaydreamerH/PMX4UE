# 可见截图的主体取景契约

截图必须回答一个观察问题，而不仅是产生 PNG。本契约是 v3 的明确迁移要求：旧 distance/height 相机和没有 `pmx4ue.subject-frame.v1` 回执的截图不能通过新验收；保留旧证据，改配置、编译桥、用新运行名重拍，不修改旧报告。

## 全身

```json
{"name":"Front","azimuth":90,"elevation":0,"fov":38,
 "framing":{"kind":"full_body","margin":0.08}}
```

azimuth 是世界坐标绕 Z 的角度，elevation 是机位仰角，fov 是视口 FOV，单位度。方位由实际模型确认，名字 Front 不代表方向正确。自动距离按当前网格包围盒八角、真实视口投影迭代求取；不修改视口尺寸，不放大输出，不限制角色必须在旧100–1200cm距离范围内。margin 是画面每侧留边比例，不是像素大小要求。

## 部位近景

```json
{"name":"FaceFront","azimuth":90,"elevation":0,"fov":38,
 "framing":{"kind":"detail","margin":0.08,
   "bone":"REPLACE_WITH_ACTUAL_HEAD_BONE",
   "offset_cm":[0,0,6],"extent_cm":[14,14,18]}}
```

骨名必须来自实际骨架；不存在就失败，不退回身体中心。offset_cm 为世界空间偏移，extent_cm 为以观察中心为原点的世界空间半宽、半深、半高。示例尺寸不是跨角色标准，agent 根据实际头部/腿部尺寸调整并看图。

不适合骨定位的区域，可用 `"bounds_fraction":[0,0,0.8]` 替代 bone：包围盒中心加半尺寸乘该向量，分量范围[-1,1]，仍需 offset_cm/extent_cm。两种目标只能选其一。不能把 Face/Stocking 名字或增加相机高度当作已瞄准该区域。

## 截图时的检查

同一个可见透视视口负责取景与捕获。截图入口在预热、贴图 mip 完整驻留、视口绘制之后，重新检查指定角色/组件存在、注册和可见状态；重新投影全身或近景目标范围，拒绝裁切、在相机后方、最大方向占画面不足一半、错误骨名和观察中心落在角色包围盒外。回执与 PNG 一起记录；离线复核核对 mesh、相机目的、目标、视口尺寸与实际投影范围。

“取景时看得见，截图时被隐藏”也必须失败，不能把先前的取景回执当作捕获时证据。保留低层通用截图方法无主体调用的用途，但这类输出不能用于本工作流视觉验收。

预热期间视口比例/相机变化导致投影失效时，最多重新取景并预热两次，保留 framing_retries 记录；持续变化就失败。缺角色、隐藏、错误骨名不走这条重试路径，不反复等待。

这些检查仍不是语义验收：包围盒可能包含松散发饰/物理范围，目标可能被地形或头发遮挡，极端透明材质也可能不可见。agent 必须打开原图确认人物、目标部位、光照与细节；错误骨名之外的“选错有效骨骼”仍需要判断。不自动批准亮度、清晰度、材质质量，不把几何投影通过说成截图一定有意义。

基线诊断可先只有全身。最终材料评审要补相关部位近景和全身，并与同机位/同光照 A/B 配对。近景新增或取景参数改变时重新做环境基线，不套用旧环境审核。
