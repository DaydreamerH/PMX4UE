# 面向 UE 重定向的骨架方案

目标：保持 UE 绑定与蒙皮可靠，让标准 FK/IK 重定向有可解释的实际主链；不要求原 PMX/VMD 控制动画兼容。源 PMX 只读。先做独立 UE 用导出变体，不动躯干/腿部来解决手臂问题。

实际改层级后，按 [协作规程](agent-collaboration.md) 优先安排另一智能体审阅导出/UE 真实层级与采样变形证据，再交付 IK/物理；不能只读规划或端点配置。主智能体维护统一语义映射，工具不足时自行复核并记录同一智能体审阅的范围。

## 默认路径：保留骨骼，整理父子级

```text
躯干
├─ 肩P及其技术辅助骨（不进入重定向主链）
└─ 肩
   ├─ 肩C及其附属结构（不进入重定向主链）
   └─ 上臂
      ├─ 上臂扭转骨及变形/挂件旁支
      └─ 肘
         ├─ 前臂扭转骨及变形旁支
         └─ 手腕
```

有权重不等于必须在主链中；需要保留不等于原层级不动。Arm→Wrist 两个 IK 端点之间仍会包含实际中间骨，不能把修改端点当作整理层级。名字含 twist/wrist/waist 时先列出实际路径和 PMX 原名，不靠字符串包含关系删骨或修改躯干腰骨。

新工作单默认 `goal=clean_ue_fk`、`shoulder_strategy=branch_helpers`；仍需 agent 映射真实骨名，不能默认 reviewed。

1. `skeleton-audit` 后按原名、父级与权重填 roles，执行 `skeleton-review`。报告的 `ue_fk_proposal` 给出动作方向，不自动签字。
2. 主链有中间骨时将对应 arms/shoulders 决策设为 optimize。肩链需要改时设 `simplify_shoulders=true`；`skeleton_policy=upper-only`。若主链已经干净可 preserve，但需说明旁支角色，不能因有扭转权重而保留脏主链。
3. `skeleton-plan → skeleton-apply`。branch_helpers 只改肩、上臂、肘、腕父级，不删除 P/C、扭转骨或挂件，也不要求填写仅删除模式才需要的 rehome 映射。
4. `ue-build` 读回实际层级，IK/物理必须使用新导出的 mesh。IK 肩链用真实肩骨，手臂链用上臂→手腕，不映射 P/C 控制骨到源运动链。
5. 静态与采样检查通过后建立 IK/重定向；有源动画时检查走路、抬臂、屈肘、扭腕及腰部连接。没有源动画只将动态验收标 pending，不撤销已完成的结构处理，也不宣称 UE 动作已验收。

## 补偿的处理边界

已实现的 P/C 分支适配支持中性 P/C、C 无追加变换或已确认的 C=-P 旋转补偿。P 保持中性，不再驱动变形主链；保留的 Blender 约束不等于它们会随 FBX 自动成为 UE 运行时约束。报告显式声明 `compatibility.target=ue_fk` 和 `pmx_control_animation_preserved=false`。

非中性控制姿势、未知补偿、已有 P/C 动作/驱动依赖需要导出适配或姿势烘焙，不能默默抹掉。这里的阻塞是为了避免改变 UE 绑定/蒙皮，不是要求恢复 PMX 控制功能。源骨骼 Morph 和挂件记录供 agent 判断；UE 骨骼 Morph 运行时、复杂 twist 自动分配不在结构改父级的保证范围内。

若确实需要更少骨数，可明确选择旧 `delete_helpers` 模式：逐骨证明无权重及无有效引用、处理所有保留子骨后删除。它不是新工作单的默认方案，不能因为删除受阻就放弃主链整理。

## 检查与迁移

- 源审计读取 mmd_tools 属性注册后的附加变换、骨骼 Morph、约束和动作，避免后台打开 blend 丢失属性注册造成误判。
- 静态位置、rest matrix、左右肩/肘/腕及组合采样与原模型比较，输出误差；父级改变后保留绑定矩阵与顶点组。
- 后置条件检查实际父级、保留辅助骨存在、应删骨确实删除。UE 再次读回；文件生成与运行成功不代表视觉合格。
- 旧工作单不会静默变更策略：显式添加 goal/shoulder_strategy，重新 audit、plan、apply、导入到新版本。勿手改旧报告为 passed。
- 尚未覆盖的复杂结构先适配，再运行同一验证；不要重复让用户解释“主链”的含义。
