# 截图分阶段保留与提前清理

本机制只管理工具生成的截图，不清理源 PMX、贴图、目标图、UE 资产或用户手动截图。截图可以在材质迭代中提前释放，不必等待角色最终交付；旧 UE 资产仍遵循最终确认和单独删除批准规则。

## 1. 采集时消除重复副本

可见视口截图先落到 `Saved/PMX4UECaptures`（旧宿主为 `Saved/MMD2UECaptures`），采集器复制到本轮产物 `captures_<token>`，完成 PNG 检查并保存报告后，核对两份文件的 SHA256 一致，再只删除本轮精确命名的原生临时副本。产物图保持原始字节、尺寸和哈希，是后续实际看图与交付的原图，不做压缩或缩略图替换。

`native_copy_retention` 记录结果和释放字节数。复制/PNG 检查未完成、文件不匹配时不删；占用或权限导致清理失败时保留两份并记录，不以删副本失败否定已经有效的截图。不要通过扫描原生目录删除其它运行或用户的图。

## 2. 每轮审阅结束做保留决策

主智能体在看图、采用/退回候选并收回子任务执行权后整理：

- 保留用户指定图、已认可基线、当前选中方案、正在比较的候选，以及下一轮仍需的故障代表图。
- 保留当前材质审阅、delivery/目标图对照、脸部转光、描边开关、物理/游戏验证引用的全部图；只要引用整个预览报告，就保留该报告的完整矩阵。
- 默认保留最近两轮仍有价值的预览，不按数量强制删；未解决故障、子任务仍在看图、用户尚未看过的交付候选不能仅因“旧”或“多”而退役。
- 已被新版本替代且不再提供独立信息的预览，记录替代运行、退回理由与准确报告路径/哈希。若旧运行记录也列有截图/报告引用，一并明确退役该 `material-preview` 运行记录；不要删除记录本身。

部分图片还被使用时，优先保留整轮。不要编辑旧捕获报告来缩小矩阵、把已删除图的哈希改成新图，或删掉引用以强行通过清理。未打开图不能按文件名判断其无用。确定性清单整理可委派，退役决定由主智能体统筹。

## 3. 引用保护、只读计划与批准

从 `templates/capture_retention.example.json` 建立本角色策略。`artifact_root` 必须在指定项目 `Saved/PMX4UE` 下限定到角色/版本；`retired_records` 只接受明确退役的捕获报告和预览运行记录，不能把 delivery、审阅、目标图档案列为豁免。用 `protected_paths` 固定基线/当前预览目录、报告或图片。`external_reference_roots` 必须列出产物目录外的工作单、审阅文档、目标图 catalog 和交接目录；不了解外部引用时先补盘点，不宣称全局安全。

```powershell
python tools/capture_retention.py plan --policy "<策略.json>" --output "<artifact_root>/_capture_retention/plan-v1.json"
```

工具扫描整个项目 `Saved/PMX4UE` 及显式外部范围的 JSON/Markdown/TXT/日志，路径或哈希引用、报告引用、保留路径均阻止删除；缺失扫描范围、损坏 JSON、文件变化、目录链接或活动工程锁会阻断。输出准确 PNG 候选、保护理由、引用指纹和可释放字节，不进行删除。不按日期/目录名推测可删项；只枚举退役捕获报告中登记、哈希一致的本轮 PNG。

向用户说明保留项、退役原因、可释放体积和准确候选清单。用户可批准本次清单，或明确授权指定角色范围内按本政策分阶段清理；未取得覆盖此次操作的授权只生成计划。不借截图授权删除 UE 资产。批准记录存到 `_capture_retention`，包含 `plan_sha256`、`approved_by` 和来自用户的 `authorization_basis`；agent 不自行伪造批准。

```powershell
python tools/capture_retention.py apply --plan "<plan-v1.json>" --approval "<approval-v1.json>" --receipt "<artifact_root>/_capture_retention/receipt-v1.json"
```

执行取得同一工程锁，重新扫描引用和哈希；变化则重新计划/批准。仅逐个删除清单内 PNG，不递归删目录。此删除不会保留图片备份，需要恢复可能须重新采图；有保留价值的故障证据先 pin，不以“可重拍”认定可删。发生错误立即停止，回执记录部分结果，不循环重试。

## 4. 历史证据与交接

捕获报告、运行记录、决定文本和清理回执保留。清理过图片的旧报告是退役历史，不再是完整可读取的视觉证据；现有截图/交付检查继续对缺图报错，不加忽略缺图的旁路。保留子集不能使旧报告重新有效；需要再次验收时用新运行重拍。

handoff 记录保留基线/当前预览、退役记录、清理策略/计划/批准/回执、释放体积、外部扫描范围和仍需保留的故障图。接手 agent 先看回执，不盲目打开已退役矩阵。每轮只拍必要的 Lit 与定点诊断仍是第一优先，清理不是扩大截图矩阵的理由。
