# Face SDF：以已认可的观感为基线

本页用于用户明确指出某个现有版本的脸部阴影“就是想要的效果”时。通用工作流仍需分析新模型，不能把旧角色的轴、UV、贴图或参数当成通用默认。**视觉认可不等于该版本已通过转头、变光或游戏性能验收。**

## 1. 先固定可复现的参考，而不是先改公式

Agent 在材质设计/审核记录中写清：参考版本的原尺寸 Lit 截图及哈希、视角、场景/曝光、实际光向；该截图对应的 mesh/脸部槽、SDF PNG 与烘焙 manifest 的哈希、贴图分辨率/方向帧数/采样数、UV 通道与镜像方向、材质父图和实例、头部前/左轴、阴影软化及色调参数。读不到的项目写未知并给检查路径，不能由画面猜测。目标只有截图时可先提取可见特征，但不能声称知道它的材质公式。

参考版本只说明“在这些已观测条件下好看”。把已认可的正面/默认日光样片作为 **look baseline**，优先在新版本复现相同的脸颊、鼻口、明暗位置；不要为了“角度数学正确”擅自覆盖用户认可的画面。新角色要重新确认实际脸壳、UV 与轴，不能直接复用另一角色贴图。

## 2. 分开记录两个量

| 项目 | 数据含义 | 例子 |
|---|---|---|
| `bake_encoding` | PNG R 通道实际存储的阈值；来自 manifest/生成代码与数据检查 | `linear_azimuth_v1`：烘焙角度除以 π |
| `light_response` | 材质在当前光向下用什么数与 R 比较；来自实际图/参数读回 | `linear_azimuth_v1`：`atan2(abs(dot(L,Left)),dot(L,Forward))/π`；`cosine_half_art`：`(1-dot(L,Forward))/2` |

同一张线性角度贴图在不同响应下会有不同观感；**有已认可版本时直接按其实际响应复现，不强制做公式 A/B**。`cosine_half_art` 是刻意的非线性时序映射，且旧式 3D dot 会随光线仰角变化；它不表示贴图变成 `cosine_half_v1`。两者在正/侧/背光端点可能看起来接近，中间角度有显著差异，因此不能只拍三张端点图。先确认 `FaceSDFTexture` 是真实 SDF 而非 Neutral、`FaceMode` 已开启、UV0/UV1 选择和 V 翻转正确、R/A 通道/左右镜像及头轴有据可查；这些错误不能靠调整阴影阈值掩盖。

通用构建器已提供构建时选择：在新版本的 `material_map.json` 中设置 `"policies": {"face_sdf_light_response": "cosine_half_art"}`；不设置时仍为 `linear_azimuth_v1`。同一 Master 的脸部槽共用此响应；若一个角色需要不同脸部槽用不同公式，应另建明确的父材质路由，不能让单一全局设置假装逐槽可选。美术响应仍复用实际线性角度 SDF 数据，不改写其编码；保留 UV、侧向翻转、R/A 采样、遮罩及头骨驱动。构建新版本后运行材质验证，必须读回实际连接的响应，再在交付记录的 `face_shading[].light_response` 中写相同值。读回失败、UE 材质未编译或没有实际 Lit 光向画面时不能宣称验证完成；`(1-dot(L,Forward))/2` 不是新角色的默认。

## 3. 直接复现与验收

1. **新烘焙固定 1024×1024。** `blender_face_sdf.py` 默认且仅接受该尺寸；审计必须回读宽高均为 1024，并核对 UE 绑定源、线性 Masks、压缩与实际驻留 mip。已认可版本若有 1024 原图，可复用其源文件与哈希，不要用旧 512 图冒充同一输入。这里是规格要求，不要求做 512/1024 对照。
2. 在新材质版本中沿用已认可的实际 `light_response`、UV、头轴、R/A 采样、阴影色与柔和度；在其原机位、Open World 日光与曝光下复现。打开原尺寸脸部近景，记录鼻口、两侧脸颊、眼周、半影与光暗方向；保存当前截图哈希与观察。无需先做严格角度与美术响应 A/B，公式一致性也不能自动推翻用户认可的画面。
3. 再做同机位至少七个相对头部光向（例如 -90/-60/-30/0/30/60/90°），必要时增加仰角、背光与头部旋转。看过渡是否可接受、是否出现整齐半脸直切、鼻口黑斑、UV 接缝、左右翻转或因太阳高度导致的异常。发现问题先定位贴图/脸壳、UV、轴、mip/压缩、响应曲线还是场景光照；只在需要排错时做单变量对照，不把对照当启动门槛。
4. 静态通过后另测头骨驱动、Actor 转向、多实例隔离；无动画时只声明静态 lookdev，不宣称运行时完成。材质图或贴图更新后旧截图过期，须重采。

## 4. 选型与交付边界

在 `templates/material-design.md` / `templates/material-review.md` 记录参考证据、真实 `bake_encoding`、1024 宽高与实际驻留 mip、选中的 `light_response`、图/实例路径、七角度及必要仰角观察、缺口与下一步。自动检查验证**所选单路径的图连接**、显式记录、绑定纹理和光向截图证据；它不判断画面质量，也不证明运行时头骨驱动或性能。未知贴图编码、未读回的图、缺失 1024 审计或缺少多光向画面均保持失败/待验收。

本页不要求复制任何历史角色的资产或名称到通用仓库。保存的是可检查的决策方法和公式差异；每个新模型都要用自己的实际数据与画面重新选择。
