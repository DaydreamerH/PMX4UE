# 日光预览：先证明画面可信，再调材质

适用于 v3 可见视口预览。默认直接加载 `/Engine/Maps/Templates/OpenWorld`；不建自定义地图、不保存模板、不提高分辨率作为通过条件。只读审计截图不启动 UE，也不修改角色。

## 分清三种“黑”

1. **PNG 透明导致显示黑/空白**：普通场景截图应该完全不透明。原生桥只在保存场景 PNG 前设置 Alpha=255，RGB 不变；不会修改角色贴图、透明材质或 SDF 的 Alpha。检查器实际解码 8-bit RGB/RGBA PNG、五种行过滤和压缩数据，拒绝任意非不透明像素。需要真正透明背景的输出应另设契约，不复用材质验收截图入口。
2. **RGB 本身过暗**：看报告 `image.pixels` 的 RGB 范围、均值、近黑/近白比例，再打开原图。统计在编码后的字节空间计算，不是物理亮度或视觉评分；暗色服装、诊断模式、局部特写都可能低亮度，因此只警告，不自动判材质失败。
3. **环境或材质局部过暗**：天空和地面正常、只有人物异常时，再比较 Lit/Unlit/WorldNormal 与实际贴图。整张图过暗时先排查相机、天空/地形加载、太阳和曝光。不能靠全局 Emissive、贴图提亮或关闭阴影补偿环境错误。

排查顺序固定为：**PNG 完整性和 Alpha → RGB 与实际视口 → 相机及环境加载 → 实际太阳方向/强度 → 曝光 → 材质**。检查太阳使用命名参数 `unreal.Rotator(pitch=..., yaw=..., roll=...)`，并对照报告回读，不能凭请求参数判断成功。

## 默认基线与 A/B；校准是可选项

1. 从 `material_preview.example.json` 开始，只有未改材质的 `Baseline`，`exposure_ev100: null`，第一盏 light 只有 name，继承 Open World 默认日光。先检查全身、近景、天空和地面；贴图 mip 就绪后采图。模板/工程自动曝光可能继续收敛，必要时增加预热并重拍。
2. 默认环境可用后，直接加入候选 case，保留 `exposure_ev100: null` 和默认太阳。无需额外试 EV100、创建曝光覆盖或提供 `environment_review`。A/B 会拍本轮 Baseline；也允许在一次采集中同时取得基线和候选，不要求先跑一个独立校准任务。
3. 打开本轮原图比较材质。默认自动曝光可能随画面适应，先等待稳定，不能只凭整体变亮判断材质改善。确实需要隔离曝光影响时才显式选择固定 EV100 并记录理由，不把 12、3 或 -2 当通用值，也不把这条可选路径变成所有角色的门槛。
4. **可选环境引用**：需要复用已审环境时，可填写 `templates/environment_review.example.json`。引用默认曝光或固定曝光的 Baseline-only 完整 v3 报告均可；必须实际打开其每张 Lit 图，并记录真实报告/图片哈希与天空、地面、人物观察。校验仍要求 mesh、位置、曝光策略、相机、灯光相同，图片不透明、贴图驻留、输入资产未变、实际太阳参数完整；引用不能继续嵌套。改变条件时更新引用，或在新 profile 中省略此可选引用重新采集，不修改旧证据。
5. 无论是否选固定曝光/环境引用，都要保留取景、贴图加载和实际看图验收。环境正常不代表材质、描边、SDF 或物理已验收。无法看图时保持 pending 并交接，不把文件检查通过写成视觉通过。

迁移：旧 v3 配置可在新运行中改为 `exposure_ev100: null`、仅保留默认太阳，并省略 `environment_review`；已有固定曝光方案仍可显式保留。记录策略变化，不改旧报告。所有旧相机配置仍须按 [主体取景契约](preview-framing.md) 迁移；旧 v1/v2 结构可读，现行执行器要求迁移到 v3。

## 编辑器进程与资源

自动采集器仍只操作自己持有的编辑器，避免加载地图、临时材质覆盖或退出操作破坏用户当前工作。这与是否固定曝光无关，也不意味着用户开着编辑器时必须立即双开。资源不足或出现显存告警时暂停采集，询问用户是否方便保存并关闭现有编辑器，之后再启动采集；不得自动关闭用户进程。当前采集器不支持接管现有编辑器，不把未实现的复用路径写成已支持功能。

## 修复截图代码之后

- 修改 C++ 源码不会更新正在运行的 DLL。按环境规则确认目标编辑器已关闭，编译对应模块，并在新自有编辑器进程采集；不得杀用户编辑器或覆盖正在使用的模块。
- 新桥返回 `alpha_policy: opaque_scene`，但最终仍以解码像素为准，不能只信这个字段。旧桥若恰好输出全不透明图仍可检查；有透明像素立即失败并记录 `invalid_capture` 原图路径，不空等60秒，也不去调灯光。
- 将旧图复制后强制不透明，仅可诊断“RGB 正常但 Alpha 坏了”，不能冒充修复后原生采集。保留原图、原报告和失败日志；**不要改旧报告哈希或用修补图替换证据**。
- 本流程不会自动认可图像清晰度或材质质量；编译通过、PNG 有效、环境已审和材质视觉通过分别记录。
