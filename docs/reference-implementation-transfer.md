# 独立工程实践的通用化接入

2026-10-01：参考 `MultiAgentsForGPT` 的实际版本脚本、专项审计、独立原图复核与交接记录，不覆盖本仓库为该工程的旧副本。参考工程只读；不复制角色资产、固定槽号/坐标、机器路径、太阳角度或候选参数为通用默认。

头发/刘海现在以 [头发渲染规范](hair-rendering-standard.md) 为默认设计基准，须完整阅读：头部空间高光、距离场额前投影、刘海深度代理与受控眉眼补绘，保留源裁切/完整眼着色和前后关系。本页只列已移植工具与仍需适配的边界，不把“可参考”误作可以跳过规范。

## 头部空间高光带

UV1 可以存在、逐值导出正确，却仍有根梢方向混用、极小岛和非归一化尺度；这时全图 V 平移容易跨岛。sphere/matcap 灰度图也不是发束 atlas。

`head-hair` 支持显式 `highlight_mode="head_band"`：在审核 profile 的 `band` 中填真实线性发束遮罩及 UV 通道、球心相对高度/宽度/视线移动量、独立高光法线混合。`tools/ue_hair_reference_nodes.py:add_head_band` 在复制父图中接入，保留完整实例继承、漫反射、透明与下游 HairMode/强度/NPR/光照门控；头骨无效时回退原高光。原 mesh、UV 与材质不改。工具缺省 `preserve` 保持兼容，不代表新角色默认完成；新角色优先拟合规范中的头部亮带，保留已认可高光须有依据。

复用共享头骨组件的 `HeadSphereCenterWS`/`HairUpRuntimeWS`，不复制另一套 Actor tick；高度以校准球心为原点，不偷用参考角色 Head 枢轴和偏移。参考 v9 确实使用 BaseColor 亮度保底调制和侧向弧度，本 helper 则要求显式遮罩且没有弧度；两者不完全相同。允许按真实纹理适配参考的亮度近似，但不能冒充已绘制发束 atlas；当前 helper 的差异按规范记录或补齐。带状高光是否足够成束仍由画面决定。

使用 `templates/head_hair.example.json` → 审核头部体积与 mask/UV → `head-hair --execute` → 用 `head_hair_report` 挂入预览。构建报告追踪遮罩指纹。高光不明显先检查完整门控，不提升整角色 OutputGain 掩盖问题。非匹配父图明确拒绝，由 agent 据实际连接适配，不靠编辑器节点坐标定位。

## 干净的刘海投影

参考失败实验表明：直接混合二值角度遮罩会出现灰块/重影，接收范围过宽还会把阴影画到眼睛和脸颊。通用策略是**先插值有符号距离，再阈值画一条边界**，接收范围来自本模型真实额头/UV/几何。

`tools/fringe_distance_fields.py` 将已经由真实几何烘焙的五角度遮罩转为距离场：

```text
python tools/fringe_distance_fields.py --angles-a <A.png> --angles-b <B.png> --output <新目录>
```

PNG I/O 需要 Pillow，不自动安装。A.R/G/B/A 分别为 -90/-45/0/+45°，B.R 为 +90°，B.A 为真实接收覆盖；A.A 是数据而非透明度。输出线性 Masks、关闭 sRGB、不另翻 UV，编码 `.5 + signed_distance/(2*radius)`，正值为阴影内部，使用截断八邻域 chamfer 近似而非精确欧氏距离。尺寸继承输入，不混称 Face SDF 编码，也不覆盖 1024 Face SDF 规范。

`ue_hair_reference_nodes.custom_node(...,"fringe_distance",bindings)` 提供可接线计算，全部输入显式给出；Receiver 为额前限定遮罩，Strength/Valid、真实头部基向量及实际主光均须接入。固定烘焙仰角、姿态和有限角度只适合相应范围。几何射线烘焙、额头选区、真实额外 Pass 挂载仍由 agent 按本模型实现；**helper 不会建立 Pass 或额外组件**，也不修改脸部 SDF。

## 眼白与虹膜一致的局部透刘海

保持主头发 Opaque/Masked，额外层只显现真实眉/睫/眼区，不整头 Translucent。共享 UV 的两眼取 min 会误裁本眼，取 union 又会放开另一眼真实遮挡。按真实两眼身份分别烘焙 R/G，运行时用头部空间侧向选择，明确左右基轴符号，不能写死世界 X。

`custom_node(...,"eye_peek",bindings)` 包含分眼孔径、专用刘海 StencilID、目标处于刘海后方的距离窗口、SceneDepth 与 CustomDepth 一致性、正面视角渐隐。深度容差依据真实间距拟合；stencil 从工程占用中分配，没有硬编码默认编号。深度代理必须只显示实际刘海槽并跟随主 mesh；组件全局 stencil 不等于已隔离内部槽。

本方案保持原不透明刘海，不做原层排除；补绘的是眼睛。helper 显式输入 `AlphaScale/SourceClip/CoverageMode`：源 Masked 使用二值裁切覆盖，连续透明源才用连续 Alpha。旧 recipe 绑定必须补这三个真实输入后重建独立候选，不默填参考阈值。

透视层复制原眼材质完整着色和参数，不仅用颜色图发光。共同权重也不能避免双重叠色：若眼白在不透明虹膜后，两层 depth-off 会额外混入白色，应先排除后方眼白，或先合成有深度关系的整眼再混合一次。保留源眼形/高光层，不移动/放大眼睛遮掩问题。静态孔径不适应眨眼、眼球转动或表情，明确记为待验。

旧 `create_bang_passes` 继续禁用。新计算 helper 不是旧半透修复证明或一键完整运行时；需明确组件/Pass 路由、源 Alpha 覆盖、排序与游戏性能证据，按 `docs/hair-bangs-workflow.md` 分开验收。

## 协作与交付经验

- 主智能体独占共享配置与 UE 队列；子智能体只改独立候选/报告，分别复核骨链、目标图材质与物理，不并发构建 UE。
- 候选锁定准确组合，允许 mesh、脸、袜、头发、描边来自不同显式版本。“最新目录”不是交付。审阅者拿原始图/输入与要求，不能只读作者总结；分别记录实际看图者和事后补哈希的元数据编写者。
- 缺陷驱动最小实验：例如先分眼 mask，不同时扩大深度、增亮虹膜与加头发槽。失败候选退回，不改原骨架/SDF/眼形隐藏问题。
- 最终组合保存后重载，读取实际 mesh、父图/MI、槽、Overlay、运行时驱动及 AnimClass。静态专项通过不能覆盖物理失败；最终组合不同于旧性能测试组合时，性能保持 pending。
- 主审与独立审阅不代替用户认可，无独立执行者注明同一 agent 复核。先两张局部 Lit 关/开，异常才扩大，不把历史数十张采图固化为默认成本。

这些规则接入协作文档与模板，不新增自动模型调度器或审批门槛。

## 未直接迁移的实验

参考 native HairPreviewActor 有另一套参数协议、重复 tick 与多个额外组件，不能直接安装到当前宿主或替换共享驱动。其局部透视静态成功不证明动态排序/表情/多实例性能。参考物理 mode 2 输出位置恢复适配有“不得有模拟祖先”的条件，且恢复后计量的位置误差不能说明原始漂移量，本轮不移植为无条件通用能力。参考记录仍有物理视觉失败、最终组合性能未测，不包装成物理通过。

本次验证限于纯 Python 算法、接线模拟、profile 和既有流程回归。UE shader 编译、组件集成、真实视觉及性能由目标工程执行 agent 实测，参考记录和逻辑测试不自动签收。
