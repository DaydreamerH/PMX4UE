目标图分析是可选环节：若提供了目标图，实际看图分析材质特征，指导实现并对照最终结果；若没有，依据 PMX、纹理与文字要求正常继续，不等待补图。详见 `docs/material-families.md`。

材质方案先依据实际 mesh、槽、UV 和贴图确认适用条件，区分已知事实与实现假设。例如丝袜的薄透观感不直接等于需要透明/透射，先查是否有独立袜层、对应皮肤底层和烘焙肤色，再做隔离对照。不要为未经验证的猜测修改几何；数据不明先查数据。

使用 PMX4UE 工作台完成角色导入与配置。先阅读工作台的 AGENTS.md、skills/pmx-to-ue/SKILL.md 和 docs/fresh-project-runbook.md。所有操作以本任务指定的目标工程为准，不依赖历史项目路径或聊天上下文。

检查本机工具、目标 UE 版本及已有插件。缺少所需能力时安装并编译适配的 PMX4UE 插件；已有实现先检查兼容性，避免重复安装。验证实际接口可用，不把路径检查当成环境验证通过。

根据当前模型数据建立角色配置，完成材质、骨骼、IK、双侧重定向姿态和 PMX 物理；需要面部 SDF 时接入头骨驱动。不要照抄其他角色的骨名、方向轴、单位或物理参数。默认保留腿骨，依据 PMX 碰撞组、双向 mask 和关节关系处理物理，不额外增加衣物避让。

先按骨骼参考运行 skeleton-audit/skeleton-review，分别决定手臂与肩膀是否清理，填写 skeleton_decision；不能因默认 preserve 未经检查就进入 IK/物理。优化时实际导入 upper_only.fbx 并使用其 mesh。已合理的链可以保留，但说明理由和证据。

材质基线后按 docs/scene-effects-workflow.md 分别处理描边、边缘光：有依据则构建并在 Open World 预览挂载，做同条件开关对照；不采用也要记录模型/目标依据。不能只生成材质就当生效，或因涉及场景就忽略。太阳旋转使用命名参数，不改用户场景来完成测试。

材质目标是角色级 lookdev，而非仅贴色。先读 `docs/material-families.md` 并完成材质设计表，按真实槽区分脸部/皮肤、头发/刘海、眼白/虹膜/高光/阴影、丝袜、不同织物/硬表面和透明件；分析高光、厚度感、描边和边缘光的实现条件。为不同计算与渲染层选择或编写专用父图/共享函数/Pass，明确父路由，不能把所有表面挂同一 Master 改颜色后交差，也不能靠复制同一图冒充专用实现。允许基于实际 UV/纹理/几何适配脚本或生成有依据的辅助资源。

用户要求或该模型参考风格所需的效果，必须实现和专项看图，或明确记录缺口；不能因旧配置写着 optional 就省略。使用隔离预览做眼睛、头发、袜类等局部 A/B，以及光照/视角和描边距离变化检查。没有源动画不妨碍静态材质调试。基础图能编译只标为 baseline_only，留下不足与下一步，不能称为已达到完整角色效果。

遵循 `docs/material-iteration-and-delivery.md`：尽早取得基线画面，新环境先做小范围兼容性探测；只调材质时用 material-build 复用 mesh/纹理，不反复全量导出导入。检查实际父图与逐槽有效输入，追踪缺资源被关闭的功能，不把止错当作完成。交接时明确资产组合、基础构建风险和各效果证据，运行 delivery-check；证据完整仍需实际看图与各运行时验收。

脸部阴影按 `docs/face-shading-workflow.md` 在首组基线后开始，静态材质交付前完成：使用 SDF 时生成或适配真实贴图、检查有效覆盖内的 R 阈值变化、核对实际绑定和开关，再看正面/左侧/右侧光照；采用替代方案时记录理由并验证同组效果。全白 Neutral、FaceMode=0 和“后续若需”都不能作为完成。缺动画只影响运行时测试，不推迟这些静态工作；交付清单 v2 必须有 face_shading 决策。

充分利用模型数据、引擎接口和画面进行判断。允许在工作台内适配脚本并补充测试；可以自行查明的信息不要反复要求用户填写。缺少关键资源或存在重大风格选择时再询问用户。

源资源及已有正式资产保持不变，新产物使用独立版本目录，不覆盖用户场景。需要关闭编辑器或进行破坏性操作时先征求同意。

分别验证导入、材质、重定向、物理和性能。没有动画时先完成静止部分，明确标记动态验收待完成。性能测试前设置并回读 t.MaxFPS 200，记录测试条件，不以平均帧率代替稳定性验收。

最后提供资产路径、可复现步骤、测试证据、未解决项和交接文档，区分自动检查、视觉确认与尚未验证的内容。未经要求不要提交 Git 修改。
